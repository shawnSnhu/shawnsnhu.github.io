Artifact narrative

Selection and improvement

The artifact is a contact management service that I originally created in my Software Testing, Automation, and Quality Assurance course in February 2026. The Java program stored contacts in a HashMap and allowed a contact to be added, updated, or deleted. JUnit tests were also included for the assignment requirements. At the time, the program contained only a few classes and did not have an external interface for interacting with it. I saw an opportunity to build on the service without starting over.

I rebuilt the artifact as a Spring Boot REST service. The enhanced version separates the controller, service, repository, and model responsibilities. It supports creating, listing, retrieving, updating, and deleting contacts through REST endpoints. Tests are included at the model, repository, service, and REST levels. Phone numbers must contain exactly 10 digits, and contact IDs are limited to characters that are safe to use in URLs. Those issues did not prevent the original assignment from working, but the code review highlighted them as areas that should be improved.

Course outcomes and skills

This enhancement demonstrates my use of Java, Spring Boot, Maven, REST, and automated testing to turn a small program into a more complete working service. Separating the controller, service, and repository layers also makes the program easier to understand and maintain. The 18 tests check duplicate IDs, missing contacts, invalid inputs, failed updates, and expected API behavior.

Outcome connection: This work most directly supports Outcome 4 through the use of established tools and layered software design. Its validation and error handling also contribute to the security mindset described in Outcome 5.

Reflection and trade-offs

Working through the enhancement helped me understand why application structure matters once a program grows beyond a few classes. Separating the repository from the service required more setup, but it made each responsibility easier to follow. Testing across layers also provided more insight into the full system than testing individual methods alone.

One design choice was whether to keep the repository in memory or add persistent database storage. Persistence would have introduced more components that needed to be developed and tested. I kept the in-memory repository because it allowed the enhancement to remain focused on application structure and software design.
