Animal Shelter Dashboard

A Python, MongoDB, and Dash application improved with database-side sorting, pagination, aggregation, safer configuration, and automated testing.

Created June 2026 Python MongoDB 15 automated tests

Before and after

Moving work closer to the data

The original dashboard worked, but it returned every matching record before sorting and pagination. The enhancement gives MongoDB more responsibility and reduces the work performed in the dashboard.

Original version

  • Python CRUD module connected the dashboard to MongoDB
  • Rescue filters returned every matching record
  • Sorting and pagination occurred after retrieval

Enhanced version

Artifact narrative

Selection and improvement

The artifact is an animal shelter database and dashboard application that I originally created in June 2026 for my Client/Server Development course. The project uses Python, MongoDB, and Dash. A CRUD module connects the application to MongoDB, while the dashboard allows a user to filter animal records by rescue type, view records in a table, see breed distribution, and display a selected animal on a map.

I selected this artifact because it was already centered around MongoDB and gave me an opportunity to improve the database operations without changing the application's main purpose. I moved rescue queries into the database module and added server-side sorting and pagination with MongoDB's sort, skip, and limit operations. I also added an aggregation pipeline that counts matching records by breed. A small sample dataset allows the dashboard to be demonstrated without access to the original course database.

Course outcomes and security

The enhanced module validates filter names, page values, page sizes, sort fields, and sort directions before running a query. Database connection information is read from environment variables instead of being stored in the notebook. Empty update and delete queries are blocked to reduce the risk of unintended changes to the full collection. The 15 tests cover filtering, sorting, pagination, aggregation, CRUD operations, invalid values, and database configuration.

Outcome connection: This work supports Outcome 4 through practical MongoDB operations and automated testing, and Outcome 5 through safer configuration, explicit validation, bounded page sizes, and protection against empty destructive queries.

Reflection and trade-offs

Moving sorting, pagination, and breed counts into MongoDB reduced the amount of work performed by the dashboard and helped me better understand how responsibilities should be divided between an application and its database. One challenge was keeping the table, chart, and map consistent when a filter or page changed. The dashboard needed to reset the current page and selected row so each component continued using the same record set.

More features could have been added, but I kept the scope focused on database operations, security, and testing. The enhancement improves credential handling and query safety, but it does not add user authentication or authorization. Those controls would be necessary before deploying the dashboard as a public production system.
